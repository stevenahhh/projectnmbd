## 2. 추천 주제 — 「지금 비어있는 강의실: 공강 강의실 파인더」

### 2.1 무엇을 만드는가

**불편의 실체**: 개설강좌 시간표는 존재합니다(학과 홈페이지·포털에 건물·호실·요일·교시 표). 하지만 **그 반대인 "지금 비어있는 강의실"은 존재하지 않습니다.** 학생은 팀플·자습 공간을 찾으려고

- 빈 열람실을 헤매거나
- 강의실 문을 하나씩 열어보거나
- 에브리타임 빈 강의실 게시판에 "공학2호관 305 비어있나요?"를 묻습니다

정보는 있는데 **역산이 없는** 것이 문제입니다.

**만드는 것**:

1. **빌드타임(내 컴퓨터)**: 공개 개설강좌 시간표를 수집 → `(건물, 호실, 요일, 교시)` 점유 집합(occupancy set)으로 정규화 → **전체 슬롯 − 점유 = 공실(vacancy) 시계열**을 집합 차집합으로 계산. 예: 공학2호관 305호의 화요일 1~8교시 중 2·3교시만 점유면 나머지는 전부 공실.
2. **런타임(Vercel)**: 정적 JSON(`data/vacancy.json`) + 요일·교시 슬라이더 + 건물 층별 색칠. 현재 시각이면 "지금 빈 방", 슬라이더를 움직이면 "3교시에 빈 방"을 즉시 필터. **지도 타일은 OSM(무료), 경로는 필요 없음 — 목록이면 충분합니다.**

핵심은 **계산이 전부 빌드타임에 끝나고, 브라우저에서는 필터만 한다**는 것입니다. AI는 시간표 파싱 정규식을 함께 다듬는 데만 쓰고, 배포본에는 AI 흔적이 없습니다.

### 2.4 Vercel Hobby 배포 설계

```
[빌드 타임 — 내 컴퓨터 / GitHub Actions]
  공개 개설강좌 시간표 수집 (학과 페이지 HTML / 엑셀)
    → 파싱 정규화: { building, room, day(월~금), period(1~8), course }
    → 점유 집합 구축: occupancy[building][room][day] = Set(period)
    → 전체 슬롯 생성: allSlots = Cartesian(건물별 호실 × 요일 × 교시)
    → 공실 계산: vacancy = allSlots − occupancy   (집합 차집합)
    → data/vacancy.json 생성  ← AI는 파싱 정규식 개선에만 참여, 여기서 끝

[런타임 — Vercel Hobby]
  Next.js 정적 페이지 (SSG) + 클라이언트 필터
  - data/vacancy.json (수십 KB)
  - 요일·교시 슬라이더 → vacancy 필터 → 리스트 렌더
  - AI 호출 0, DB 0, API 키 0, 크론 불필요, Edge Function 불필요
  - 지도 붙이면 Leaflet + OSM 타일 (client-only, 무료)
```

**Hobby 제약 대비**:

| 제약 | 값 | 이 설계 |
|---|---|---|
| Cron 1일 1회 상한 | 더 잦으면 거부 | **크론 불필요** — 시간표는 학기 고정, 수동 재배포로 충분. 필요해도 24h ISR 1회면 됨 |
| Supabase 7일 pause | 08-30 제출→09-07 심사 8일 | **DB 없음** |
| Active CPU 4h/월, 함수 10s | 초과 시 일시정지 | 정적 서빙이라 CPU 0에 가까움, 함수 0개 |
| Fair Use / Bandwidth 100GB | 초과 시 일시정지 | JSON 수십 KB × 1만명도 1GB 미만 |
| CORS | 학교 소스 전부 헤더 없음 | **빌드타임에 수집**하므로 런타임 CORS 이슈 없음 |

> **데이터 소스 확보 전략**: 개설강좌 시간표가 로그인 뒤에만 있으면 **1개 학과·2개 건물(본인 수강 건물)만 수동 시딩**합니다. 30개 강의실 × 5일 × 8교시 = 1,200 슬롯이면 데모에 충분하고, 방법론을 명시하면 "전수"가 아니어도 **기능 충실도 감점 사유밴 되지 않습니다.** (1안도 30~50건으로 충분하다고 명시했습니다.)

### 2.5 실행 가능성 — 3일 안에 끝나는 이유

- **데이터가 작습니다.** 1개 학과 시간표는 수백 행, 공실 JSON은 수십 KB. 파싱 실패해도 수동 보정 1시간이면 됩니다.
- **계산이 단순합니다.** 차집합 한 번으로 끝나고, 브라우저에서는 `Array.filter`만 합니다. Web Worker·최적화·알고리즘이 필요 없습니다.
- **UI가 단순합니다.** 슬라이더 + 리스트 + "지금 빈 방 N개" 배지. 1안의 검색창만큼이나 구현이 가볍습니다.
- **검증 부담이 없습니다.** 졸업요건 자가진단기처럼 "판정이 틀리면 0점"인 도구가 아니라, 시간표가 맞으면 공실도 맞습니다. 오답 리스크가 구조적으로 없습니다.

**이미 검증된 패턴 재사용**: 1안에서 검증한 Next.js ISR(30m)·정적 JSON·클라이언트 필터 패턴을 그대로 씁니다. 새로 검증할 것이 거의 없습니다.

### 2.6 MVP 범위와 컷라인

**반드시 (이것만 해도 완성품입니다)**
1. `vacancy.json` — 1개 학과 또는 2개 건물(공학2호관 등 본인 수강 건물), 5일×8교시 공실 데이터
2. 요일·교시 슬라이더 + "지금 빈 방" 리스트 (현재 시각 자동 선택)
3. 건물·호실 표기 + 층 정보 (예: "공학2호관 305호 (3층)")
4. 원본 시간표 출처 표기 ("데이터: 2026-2학기 개설강좌 시간표, 08-28 수집")

**있으면 좋은 것**
5. "N분 후 수업 있음" 배지 (다음 점유까지 카운트다운)
6. 즐겨찾기(로컬스토리지) — 자주 쓰는 건물 필터
7. 공유 URL(쿼리스트링에 요일·교시 인코딩)

**컷라인 — 시간이 없으면 버릴 것**
8. 층 평면도 SVG·실내 내비(발품 필요, 3일 병목)
9. 실시간 점유 센싱·제보 기능(DB 필요, 오히려 위험)
10. 전 건물·전 학과 전수 수집(1안처럼 샘플로 충분)
11. 예약·알림·캘린더 연동

## 3. 검토한 대안 — 왜 이들을 제쳤는가

Architect와 Ultrabrain이 독립적으로 뽑은 6개 중 2안을 제외한 4개입니다. 모두 런타임 LLM이 아니고 Vercel 배포 가능하지만, **심사 4일 창과 3일 구현 제약을 함께 통과하지 못했습니다.**

### 대안 B — 「시간표 충돌 리졸버: 클릭 0회 수강계획」 (Ultrabrain ★ 준우승)

수강편람을 빌드타임에 파싱해 `courses.json`으로 만들고, 브라우저 Web Worker에서 **제약 충족(CSP) 백트래킹**으로 "졸업요건 남은 과목 + 시간 충돌 없는 조합"을 뽑아주는 도구. "공강 최대화 / 1교시 회피" 슬라이더로 Top-N을 랭킹합니다.

- **강점**: 독창성 만점 후보. 12개 챗봇이 "뭐 들을까요?"를 LLM에 묻는 동안 이건 **알고리즘이 정답을 계산**합니다(LLM은 시간표를 환각할 수 있지만 이건 틀릴 수 없다는 대비). 문제도 매학기 전원이 겪습니다.
- **왜 2위가 됐는가**: **구현 리스크** — CSP 탐색·pruning·졸업요건 룰 DSL이 3일 안에 "오류 0개"로 마무리되기 어렵고, UI가 시간표 그리드라 2안-A의 슬라이더보다 복잡합니다. 데이터도 수강편람 + 졸업요건 두 소스를 동시에 맞춰야 합니다. **천장은 높지만 바닥이 낮습니다.**

> **승격 조건**: 시간이 1일 더 있거나, 본인 학과 편람 1개와 졸업요건 1개를 수동 시딩해도 "충돌 없는 조합 Top-5"까지만 약속한다면 충분히 1등감으로 승격 가능합니다. 2안-A와 메커니즘이 달라 병렬 제출이 아니라 **택1**입니다.

### 대안 C — 「졸업요건 자가진단기」 (Architect B)

수강내역을 붙여넣으면 졸업까지 남은 학점·필수과목을 **클라이언트 규칙엔진(JSON DSL)**이 결정론적으로 판정. 성적은 서버로 안 올라가 프라이버시가 세일즈포인트.

- **강점**: 지속가능성 10점 만점(학과가 규칙 JSON만 갈면 영구), AI 개발일지 소재 풍부.
- **왜 제쳤는가**: **오판정이 곧 0점**입니다. 요건표가 학번·학과별로 제각각이라 규칙 스키마가 금방 복잡해지고, 틀린 판정 한 번이 "실제 작동 15점"을 날립니다. 2안-A는 틀릴 일이 구조적으로 없습니다.

### 대안 D — 「공지 변경 감지기: 스냅샷 diff」 (Architect C)

공지 게시판 HTML을 주기 스냅샷 → 해시·텍스트 diff → "마감일이 언제 어떻게 바뀌었는지" 타임라인. 메커니즘은 **콘텐츠 원장(ledger)**, LLM 아님.

- **강점**: 각도가 가장 참신합니다. 아무도 안 본 틈새라 독창성 15점 천장.
- **왜 제쳤는가**: **심사 4일 창에 변경 이력이 빈약**합니다. 과거 스냅샷을 미리 축적해두지 않으면 데모가 "변경 0건"으로 끝납니다. 축적을 미리 해두는 것 자체가 08-28 이후에 급조하기 어렵습니다.

### 대안 E — 「실내 내비」 / 「버스 도착 보드」 (Ultrabrain A/C — 폐기)

실내 내비는 층 평면 폴리곤 수집이 3일 병목, 버스 보드는 국토부 API 의존 + 기존 버스앱과 차별성 약 + 외부 장애가 심사 중 단일 실패점이라 제외했습니다.

**스코어 비교 (Architect·Ultrabrain 합산, 100점 만점 가채점)**

| 후보 | 독창 15 | 문제 10 | 구현 35 | AI 20 | 지속 10 | 전달 10 | 합계 | 비고 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| **A 공강 파인더(채택)** | 14 | 9 | **32** | 16 | 9 | 9 | **89** | 바닥 높음 |
| B 충돌 리졸버 | **15** | 10 | 28 | **18** | 9 | 8 | 88 | 천장 높음, 리스크 있음 |
| C 졸업진단기 | 14 | 9 | 26 | 17 | **10** | 8 | 84 | 오판정 리스크 |

## 4. ★ 개발일지 — 2안만의 20점 서사

1안과 같은 20점이지만 **소재가 다릅니다.** 1안이 OCR이었다면, 2안은 **파싱·집합·UI**입니다. 같은 일지를 재탕하면 심사위원이 알아봅니다.

**목차 (이대로 쓰면 됩니다)**

1. **막힌 지점 #1 — 시간표 HTML이 제각각이었다**
   - 증상: 학과별로 `<table>` 구조가 다르고, "월1,2" / "월 1-2교시" / "화 3" 표기가 혼재. 정규식 1개로 안 됐다.
   - AI와 함께 세운 가설 3개와 검증 (정규식 분기 vs AI 구조화 vs 수동 매핑)
   - 해결: `day + period` 토크나이저 분리 → `parseSlot("월1,2") → [{day:1, period:1}, {day:1, period:2}]` (before/after 캡처)
2. **막힌 지점 #2 — "전체 슬롯"을 어떻게 정의할 것인가**
   - 1교시~8교시 고정 vs 건물별 운영시간 다름 → 결정: 1~8교시 고정, 예외는 건물별 `operatingHours.json`로 분리
3. **프롬프트 설계와 반복 개선**
   - v1: "이 HTML에서 시간표만 JSON으로" → 출력이 자유서술이라 파싱 불가 → v2: `responseSchema`로 `{building, room, day, period}` 강제 → v3: 병합셀(rowspan)·비고란 제외 규칙 추가. **각 버전 프롬프트 전문과 출력 샘플을 그대로 붙일 것**
4. **AI에게 맡기지 않은 판단**
   - 왜 실시간 센싱·제보 기능을 버리고 **역산**을 택했는가 (심사 중 죽지 않는 설계)
   - 왜 전 건물 전수가 아니라 2개 건물 샘플로 약속을 줄였는가 (기능 충실도 방어)

**핵심**: 1안과 마찬가지로 프롬프트 전문·오류 메시지·before/after를 **날것 그대로** 넣으세요. 정리된 회고보다 시행착오 흔적이 점수입니다.

## 5. 전시물 설계 — 슬라이드와 OG 카드

### OG 태그 (14개가 비워둔 자리)

```html
<meta property="og:title" content="지금 비어있는 강의실 — 공강 강의실 파인더" />
<meta property="og:description" content="시간표는 있는데 빈 강의실은 아무도 계산해주지 않습니다. 개설강좌를 뒤집어 지금 비어있는 방을 한 화면에." />
<meta property="og:image" content="https://.../og.png" />  <!-- 1200×630 -->
```

`og:image`에는 **왼쪽에 개설강좌 시간표 원본, 오른쪽에 "지금 빈 방 12개" 리스트**를 나란히 넣으세요. 1안의 "원본 PNG vs 검색 결과"와 같은 구도라 포트폴리오 일관성이 생깁니다.

### 제출 필드 초안

- 제목: `지금 비어있는 강의실`
- 한 줄 소개: `개설강좌 시간표는 있는데 빈 강의실은 아무도 계산해주지 않습니다. 시간표를 뒤집어 요일·교시별 공실을 한 화면에 보여줍니다.`
- 해시태그 8개(하나도 비우지 마세요): `순천대` `공강` `강의실` `시간표` `빈강의실` `팀플` `바이브코딩` `Nextjs`

### PDF 구성 (8~10장)

1. **표지 = 썸네일**: 08:00~22:00 타임라인에 점유(회색)/공실(초록)을 색칠한 1일 뷰. 제목 오버레이. — 이 한 장이 격자에서 첫인상을 결정합니다.
2. 문제: "정보는 있는데 그 반대가 없다" — 개설강좌 표 vs 빈 강의실 게시판 스크린샷
3. 문제의 크기: 공강 시간·팀플 공간 수색이 매일 반복됨
4. 해결: 슬라이더 시연 — "화요일 3교시 → 빈 방 12개" 캡처 2장
5. 접근 방식 차별성: **"다른 서비스는 런타임에 AI를 부릅니다. 이건 집합 차집합 한 번입니다"**
6~7. 개발일지 요약 2장 (파싱 실패→해결 before/after)
8. 학내 도입 시나리오 (시설과·교무과가 JSON 한 줄로 유지)
9. 링크 모음 (배포 URL, /devlog)

**첫 화면 30초**: 로그인·빈 상태·로딩 없이 **요일·교시 슬라이더와 빈 방 리스트가 이미 채워진 상태**. 심사위원이 슬라이더를 한 번만 움직여도 결과가 바뀝니다.
